# d18: A2, a cue's detail (dirac, sonnet, branch `wp/dirac-cue-detail`)
**Why:** A2 shows the worst moment with the cue drawn on the video, the cue's plot over time against its zones, its tiles,
the cue and how it's scored (docs/ui-design.md, A2). s4's `drawCue`, `tiles` and `referenceLine` give the content; the
plot is the app's own, mobile-first (the old panel's `mount()` isn't reused). Screens follow the mockups (docs/ui-design.md, design/mockups/); what they don't settle goes under "Needs a decision", and screenshots stay out of git: describe them.
**Read:** docs/ui-design.md; design/mockups/CueDetail.dc.html; app/README.md; the folders `app/src/scoring/` and
`app/src/draw/`; s4's API on the `Diagnostics` object and the old panel's `drawChart` for what a plot shows (zones, the
phase, the reference line), both in `diagnostics.js` in `src/`, by section.
**Red first:** yes
1. Tests first, `tests/app/cue-detail.test.js`: the plot's geometry as plain functions (time and value scales, the zones
   from the cue's thresholds, the phase band, the reference line, the worst moment's marker) against a fake 2D context;
   the tiles and the texts straight from s4's API. They fail on phase-0.
2. `app/src/draw/` gets the plot (plain canvas; a tap on it seeks); the screen as drawn: the frame at the worst moment
   with `drawCue` over the skeleton, the plot, the tiles, the cue, how it's scored, "provisional" where it is.
**Done when:**
- every number and word on the screen comes from `diagnostics.js` through s4's API or the view model;
- `npm test`, `npm --prefix app test` and the Python tests pass.
