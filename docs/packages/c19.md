# c19: the service worker, the app offline (curie, sonnet, branch `wp/curie-service-worker`)
**Why:** The app works with no network at all (rules-core.md, "Offline"): the PWA's service worker precaches dirac's app
shell, TF.js, the weights and the fonts (docs/app-plan.md, "The pieces"). d3's assemble writes `files.json` with a
version hash for it; an update waits until no job runs.
**Read:** docs/app-plan.md ("The build", "The pieces"); app/tools/assemble.mjs; app/index.html; app/README.md; the queue
in `app/src/analysis/`.
**Red first:** yes
1. Tests first, `tests/app/sw.test.js`, against a fake Cache Storage and fetch: install precaches every file in
   `files.json`; every app file is answered from the cache, never the network; a new version installs alongside and
   takes over only when the queue is idle; old caches go after; a listed file that's missing fails the install loudly.
   They fail on phase-0.
2. `app/sw.js` (scope `./`), its registration (a small module the shell calls; "update ready" as a plain line on H that
   dirac styles later), and its hook to the queue's idle state.
3. A headless check in Brave on the laptop: load the assembled app, go offline over CDP
   (`Network.emulateNetworkConditions`), reload: the app and the engine's weights load, and no request fails. Your
   worktree has neither the TF.js bundle nor the weights (both gitignored): run `node app/tools/build-tfjs.mjs` (its
   clones are cached outside the repo) and `app/tools/fetch-models.sh` first, then assemble.
**Done when:**
- the offline reload works (say how you checked); the worker caches only the app's own files;
- `npm test`, `npm --prefix app test` and the Python tests pass.
