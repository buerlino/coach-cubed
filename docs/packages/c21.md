# c21: the page test, offline (curie, sonnet, branch `wp/curie-page-test`)
**Why:** Step 5.6 asks for a headless page test that loads the app offline, runs a lateral raise and a snatch, and fails
on any console error, 404 or empty cue list; the pipeline runs it as `npm --prefix app run test:page` once the script
exists, on every run that touches `app/` or `src/`. So it must be quick and run in a pipeline worktree, which has no
example clips, on a laptop shared with pascaline's nights.
**Read:** docs/app-plan.md ("The build"); app/README.md; app/package.json; app/tools/assemble.mjs; app/tools/serve.mjs;
spike/pose-bench/run-cdp.mjs; tests/fixtures/README.md.
1. A test build: an assemble option that swaps the pose engine for a replay of a committed fixture track through the same
   worker messages (contract 1); the shipped `dist/` never contains it.
2. `app/tools/page-test.mjs` and the `test:page` script: assemble the test build, serve it on `$COACH_PORT`, headless
   Brave or Chromium over CDP (found, or given by an option; none found is a skip with a clear line, never a pass), go
   offline after the first load, then H, import, mark, analyse, result for a lateral raise and a snatch: our own test
   clip (`tests/app/clips/`) decoded for real, the replayed tracks for the keypoints. Seconds, not minutes.
3. An option for the real thing: the example clips' folder (read-only, never copied; the `phase-0` worktree's
   `tests/fixtures/local/`, found with `git worktree list`) and the real engine (software WebGL: minutes; take the
   `host-cpu` lock with `pipeline/devlock.sh` and nice the browser).
4. Fail on a console error, a failed request, an unhandled rejection, an empty cue list, or a job that doesn't finish in
   its time.
**Done when:**
- `npm --prefix app run test:page` passes on this laptop in under a minute, and skips cleanly without a browser;
- the real option ran once, and its time is in the report;
- `npm test`, `npm --prefix app test` and the Python tests pass.
