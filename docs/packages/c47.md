# c47: a test's browser ends with the test (curie, sonnet, branch `wp/curie-browser-reaper`)
**Why:** on 2026-11-02 the laptop ran out of memory during faraday's night (VSCode was OOM-killed at about 18:50, d22's
fix round died with it). 90 headless Brave instances were still running, ~33 GB, the oldest 18 h old, all children of
systemd, with profiles `/tmp/coach-page-profile-*`, `coach-check-media-*`, `coach-check-pose-*`, `coach-check-tfjs-*`
and `coach-offline-profile-*`. The cause: `/usr/bin/brave-browser` → `/opt/brave.com/brave/brave-browser` is a bash
wrapper whose last line is `"$HERE/brave" "$@" || true`, **without `exec`**. The tools spawn that wrapper, and
`browser.kill()` (app/tools/page-test.mjs:393; check-tfjs.mjs:123, check-offline.mjs:189, check-pose.mjs:161,
check-media.mjs:168) signals only the wrapper: bash exits, the real browser and its GPU process are orphaned. Every
page check leaks one (~0.5 GB), and `test:page` runs in every app run since c21. d46's fix 1 (wait for the exit)
waited on the wrapper's exit, so it did not help. Fedora's chromium is a wrapper too, so resolving Brave's path alone is
not the fix. A test killed from outside (the pipeline's `timeout 1800`, a session ended) also never reaches `finally`.
**Read:** app/tools/page-test.mjs (`findBrowser()`, the spawn at :165, the `finally` at :389); app/tools/check-tfjs.mjs,
check-offline.mjs, check-pose.mjs, check-media.mjs (each one's spawn and `finally`); tests/app/page-test.test.js;
pipeline/pipeline.sh `own_sh` and docs/pipeline.md "runs left behind when their pipeline was killed" (checks run in a
session of their own that the pipeline signals); app/README.md (the tools' section, by section). The bundle stops
after app/README.md, check-tfjs.mjs and page-test.mjs: read check-offline.mjs, check-pose.mjs, check-media.mjs,
tests/app/page-test.test.js, pipeline/pipeline.sh and docs/pipeline.md yourself.
**Red first:** yes
1. Tests first, in a new tests/app/browser.test.js:
   - static: none of the five tools calls `spawn(` on a browser itself; each launches and closes it through the helper
     of step 2;
   - live, skipped with a stated reason when no browser is found (as page-test's `COACH_PAGE_TEST_SKIP`): launch through
     the helper with the browser `findBrowser()` finds (on this laptop the wrapper above), close it, and within 5 s no
     process has the profile's path in its command line (read `ps -eo pid,args`; it works on Linux and macOS);
   - live: a child `node` script launches a browser through the helper and is sent SIGTERM (what `timeout` sends);
     after the child exits, within 5 s no process has that profile in its command line.
   They fail on phase-0.
2. A helper, app/tools/browser.mjs: `findBrowser()` (moved from page-test.mjs, with its `--browser` /
   `COACH_BROWSER` and PATH lookup) and `launchBrowser(profile, args)` returning the child, its DevTools port and
   `close()`. `close()` ends the whole tree: the wrapper's descendants found by `pgrep -P` recursively (in Linux and
   macOS alike; Noah runs macOS, c40), SIGTERM, wait up to 5 s, then SIGKILL what is left; idempotent. Don't spawn
   with `detached: true`: the browser must stay in the check's session so the pipeline's own kill still reaches it.
   While a browser is open the helper ends it on the process's SIGTERM, SIGINT and SIGHUP (then exits with the
   signal's code) and on `exit`. A SIGKILL to node can't be caught: say so in the helper's header.
3. The five tools use the helper; their own `findBrowser`/spawn/kill code goes. The check-*.mjs tools keep their
   `--browser` default behaviour (the helper's lookup). Each still removes its profile after `close()`.
4. app/README.md's tools section says why the helper exists (the wrapper without `exec`) and that a SIGKILL'd test
   can still leave a browser behind.
