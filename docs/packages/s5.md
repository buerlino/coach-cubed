# s5: the app's contracts (schrödinger, opus, branch `wp/schroedinger-contracts`)
**Why:** docs/pipeline.md: interfaces between owners are agreed in a package of their own before both sides build on
them. docs/app-plan.md ("The contracts") lists five: the pose worker's messages, an analysis job, a stored lift, the cue
view model, a frame source. schrödinger's s9–s12, curie's c8 and dirac's d13–d25 build on them.
**Read:** docs/app-plan.md ("The contracts", "The pieces"); docs/ui-design.md ("The look": the status words);
spike/pose-bench/pose-worker.mjs; spike/pose-bench/lib/pose-client.mjs; docs/fixture-data-contract.md (`track.json`);
tests/fixtures/README.md; app/README.md; s4's API on the `Diagnostics` object (`diagnostics.js` in `src/`, by section).
**Red first:** yes
1. Tests first, `tests/app/contracts.test.js`: for each contract a valid example passes and each broken field is named
   in the errors; a track in the fixture format round-trips; keypoints are COCO-17 `[y, x, conf]` in frame pixels, 17
   points or `null` (rules-core.md, principle 4). They fail on phase-0.
2. `app/src/contracts/`: one module per contract with its JSDoc typedef, a `validate…(value)` returning a list of errors,
   and a small valid example; plain modules with no dependencies, importable from a worker. Contract 2's `source` is the
   stored lift's video path (the cut kept at Analyse, nordmu's D6; s32 makes it), never a `File`, and its range is in the
   cut's timeline, so a queued job survives a restart; its validator refuses anything else.
3. The cue view model: name the source of each field in its JSDoc (`computeResults()`, s4's API, or the adapter); the
   status words are ui-design.md's: good, watch, work on, can't score.
4. A "Contracts" section in app/README.md: what each one is for, who produces and who consumes it, and that a change to
   one is a package of its own.
**Done when:**
- the five contracts exist with validators, examples and tests;
- the pose messages are pose-bench's, trimmed to MoveNet (no detector options);
- `npm test`, `npm --prefix app test` and the Python tests pass.
