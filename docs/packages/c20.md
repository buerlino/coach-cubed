# c20: the Capacitor shell, and the engine on the phone (curie, sonnet, branch `wp/curie-capacitor`)
**Why:** 0.1.0 ships as a PWA and as an APK from one web app (rules-core.md); the spike's throwaway shell showed
Capacitor 8.5.3 running the engine in the WebView. The app needs its own shell around `app/dist/`. Debug APKs only until
the name, the package ID (question 10) and the signing key's holder (6.2) are settled. It runs early, after s10 and before
the screens, so the from-source engine meets real hardware before the UI builds on it; H is still a placeholder.
**Read:** spike/webview-shell/README.md; spike/webview-shell/build.sh; spike/webview-shell/package.json; app/README.md;
app/package.json; docs/app-plan.md ("The pieces"); THIRD_PARTY.md; the folder `app/src/pose/`.
1. `app/android/` from `npx cap add android`, with `@capacitor/core`, `cli` and `android` 8.5.3 (MIT) pinned in
   app/package.json; `capacitor.config.json` with `webDir` `dist`, a placeholder app ID named as such in app/README.md,
   the name "coach"; no camera permission before milestone B.
2. `app/tools/build-apk.sh`: s6's bundle and weights built first (`app/tools/build-tfjs.mjs` and
   `app/tools/fetch-models.sh`; the cache is outside the repo), so assemble puts them in `dist/`; then assemble,
   `cap sync`, Gradle niced to one worker (the laptop is shared), a debug APK, never signed for release; build outputs
   gitignored, the generated project committed.
3. A check page assembled only into the debug build, never into the shipped `dist/`: file import through `<input
   type="file">`, WebGL, OPFS and `persist()`; and the engine on frames of s9's test clip. The service worker isn't
   needed inside the APK: register it only where it helps, and say what you chose.
4. On the Fairphone (docs/pipeline.md, "The phone": its lock, `adb -s 4d42e62f`), by day: the phone is nordmu's, and
   nordmu knows the run is happening. If the lock is busy, say so in the report and stop. Install, open, run the check
   page, report what worked, uninstall.
5. The engine on the phone, report only: in the debug APK, s10's engine runs on frames of s9's test clip from
   `tests/app/clips/`. This is the from-source WebGL bundle's first run on real hardware: it loads, gives 17 keypoints a
   frame, and the ms per frame (the median of five runs) goes in the report beside pose-spike.md's (in `docs/`) MoveNet
   Thunder WebGL row for the Capacitor WebView.
**Done when:**
- a clean checkout builds the debug APK with the script, and it opens the app shell on the Fairphone;
- the shipped `dist/` (assemble without the debug option) has no check page;
- the report gives the check page's results and the engine's load, keypoint count and ms per frame on the phone, or
  why it couldn't run;
- Capacitor is in THIRD_PARTY.md's section "In the new app (`app/`)";
- `npm test`, `npm --prefix app test` and the Python tests pass.
