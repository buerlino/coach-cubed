# c43: no Android backup, so the privacy text holds (curie, sonnet, branch `wp/curie-no-backup`)
**Why:** S1's privacy text says the app keeps the lifts "in its own private storage on this phone, and nowhere else"
(app/src/ui/settings-model.mjs:131), but app/android/app/src/main/AndroidManifest.xml:5 has `android:allowBackup="true"`,
so Android may copy the app's data (the WebView's storage, the lifts' videos included) to the user's Google Drive, or to a
new phone in a device-to-device transfer. nordmu decided on 2026-11-02: backup off, and the text approved as written
once it is true; the on-screen "Draft text, for nordmu to approve." tag goes (d24's report, item 2). The app targets SDK
36 (app/android/variables.gradle): from Android 12 on, `allowBackup="false"` stops the cloud backup but not the
device-to-device transfer; that needs `android:dataExtractionRules`.
**Read:** app/android/app/src/main/AndroidManifest.xml and app/android/variables.gradle (short; the bundle leaves .xml
and .gradle files out, so read them yourself); tests/app/android-shell.test.js;
app/src/ui/settings-model.mjs; app/src/ui/screens/S1.mjs; tests/app/settings.test.js; app/README.md (the Capacitor
shell's section, by section).
**Red first:** yes
1. Tests first, in tests/app/android-shell.test.js (static, as the file's other tests): the manifest's `<application>`
   has `android:allowBackup="false"`, names a `android:dataExtractionRules` resource that exists under
   app/android/app/src/main/res/xml/, and that file excludes every domain (root, file, database, sharedpref, external)
   from both `<cloud-backup>` and `<device-transfer>`. In tests/app/settings.test.js: `PRIVACY` has no draft text and S1
   shows no draft tag. They fail on phase-0.
2. The manifest change and the rules file (app/android/app/src/main/res/xml/data_extraction_rules.xml). No other
   manifest change.
3. The draft tag goes: `PRIVACY.draft` in app/src/ui/settings-model.mjs and its line in app/src/ui/screens/S1.mjs; the
   comment above `PRIVACY` says nordmu approved the text on 2026-11-02. The text itself is unchanged.
4. app/README.md's shell section says why backup is off (the privacy text) and what c26 checks on the phone: the
   installed package's flags show no backup. Building the APK and the phone check are c26's, not this package's.
**Done when:**
- `allowBackup` is false and the extraction rules exclude every domain from both cloud backup and device transfer
  (step 1's tests);
- S1 shows the privacy text without the draft tag, the text unchanged;
- `npm test`, `npm --prefix app test` and the Python tests pass.
