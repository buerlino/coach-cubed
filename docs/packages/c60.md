# c60: milestone A on the Samsung S8+ (curie, opus, branch `wp/curie-milestone-a-s8`)
**Why:** Question 3 names three test phones; the public 0.1.0 waits for a run on the Samsung Galaxy S8+ with Google's
Chrome and WebView (docs/'s app-plan.md, "Before the public 0.1.0"). nordmu, 2026-11-03: the S8+ runs `c60` after
`c26`, on Chrome 101 as it is (the oldest Chrome likely to meet the app), and he won't update it. The phone: serial
`ce011711cdc8a10c05`, SM-G955F (Exynos 8895, Mali-G71), Android 9 (SDK 28), about 3.7 GB RAM, Google's Chrome
101.0.4951.61, which is also its WebView (`com.android.chrome`), so the APK and the browser run the same engine.
nordmu, 2026-11-04: c60 is split; `c65` (laptop only, before this run) built what Chrome 101 lacks: the `100dvh`
fallback, the decode loop without the decoder's `dequeue` event (Chrome 106), the phone tools for any coach phone
(phone-sample.sh's serial, OMX decoder names, the idle count at the phone's own M size), and a probe in the check page
(`c20.compat`). This package is the phone run alone: it installs both shells, runs c65's probe, walks milestone A as
`c26` did on the Fairphone (report `a51b9e8`; its numbers in docs/pose-spike.md, "The app itself on the Fairphone
(c26, 2026-11-03)"), measures, and compares. The Chrome versions c65 wrote down are from memory: the probe checks
them. Not known until the phone says: OPFS with `createWritable` on Android's Chrome 101 (the store has no fallback
without it), TF.js WebGL on the Mali-G71, and how the 3.7 GB fare.

1. The phone, by day, with nordmu told. The run is started with `COACH_PHONE=ce011711cdc8a10c05` (the pipeline's adb
   wrapper allows only that phone and sets `ANDROID_SERIAL` to it); if `adb -s ce011711cdc8a10c05 get-state` is
   refused, the run was started without it: say so and stop. Its lock is its own, per serial, in the same place as
   the Fairphone's (pascaline's nights use the S8+ too): `pipeline/devlock.sh acquire ce011711cdc8a10c05 curie-<run>
   1800`, taken once, released at the end with `pipeline/devlock.sh release ce011711cdc8a10c05 curie-<run>`. This
   run never touches the Fairphone (`4d42e62f`) and needs no lock of it. Name the phone in every adb command
   (`adb -s ce011711cdc8a10c05 …`). If the lock is busy, the phone missing, or it shows `unauthorized` (nordmu taps
   "Allow USB debugging"), say so and stop. Before anything, write down how the phone is: `settings get` of
   `stay_on_while_plugged_in`, `screen_off_timeout`, `airplane_mode_on`, Wi-Fi and mobile data, the brightness;
   `pm list packages -3`; Chrome's open tabs (`/json/list` over the DevTools forward), and a screenshot of the home
   screen. `pipeline/stay-awake.sh ce011711cdc8a10c05` saves its originals only when none are saved yet: compare
   `ce011711cdc8a10c05.orig` (from 2026-10-11, in the shared `.coord/devices/` beside the locks: STAY_ON 0,
   SCREEN_OFF 600000) with what you found, and put back what you found. Battery under 25 %: lower the brightness
   (note it first); under 10 %: stop. Let it cool above about 35 °C.
